# АБС Контроль

Android-приложение (Kotlin + Jetpack Compose) для контроля укладки асфальтобетонной
смеси по нормативной таблице расхода. Работает полностью офлайн, данные хранятся
на телефоне (Room/SQLite).

## Важно: как вы получите APK

Я написал **весь исходный код** проекта — это готовый проект Android Studio. Но
собрать `.apk` (превратить код в установочный файл) в моей текущей среде я не могу:
у меня нет доступа в интернет и не установлен Android SDK, а без них компиляция
Android-проекта физически невозможна. Я не стал имитировать сборку — вместо этого
даю два реальных рабочих способа получить APK ниже. Оба проверены как стандартные,
рекомендованные способы для проектов такой структуры.

### Вариант А — Android Studio (рекомендуется)

1. Скачайте и установите [Android Studio](https://developer.android.com/studio) (бесплатно).
2. Откройте: File → Open → выберите папку `AsphaltCalc`.
3. Android Studio сама скачает нужную версию Gradle и все зависимости при первой
   синхронизации (подтвердите все всплывающие подсказки — на это нужен интернет
   один раз, при первом открытии).
4. Подключите телефон по USB (включите "Отладку по USB" в настройках разработчика)
   или создайте эмулятор — и нажмите ▶ Run.
5. Либо получите файл: Build → Build App Bundle(s) / APK(s) → Build APK(s).
   Готовый файл появится в `app/build/outputs/apk/debug/`.

### Вариант Б — сборка в облаке (без установки чего-либо)

В проекте уже лежит `.github/workflows/build-apk.yml` — настройка для GitHub Actions.

1. Создайте бесплатный аккаунт на [github.com](https://github.com), если его нет.
2. Создайте новый пустой репозиторий и загрузите в него содержимое папки
   `AsphaltCalc` (можно просто перетащить файлы через веб-интерфейс GitHub —
   drag-and-drop, без командной строки и без git).
3. Откройте вкладку **Actions** в репозитории — сборка запустится автоматически.
   Через 2–4 минуты в разделе Actions → (ваш запуск) → Artifacts появится
   `abscontrol-debug-apk` — скачайте и распакуйте, внутри `app-debug.apk`.
4. Если шаг `Setup Gradle` вдруг упадёт из-за переименования экшена — зайдите на
   github.com/gradle/actions и поправьте версию в workflow-файле на актуальную.

### Установка APK на телефон

Скопируйте `app-debug.apk` на телефон и откройте файл. Android спросит разрешение
на установку из неизвестных источников — разрешите для этого файла/приложения.
Подписи разработчика не требуется, это обычный debug-билд для личного использования.

## Что реализовано (по вашим пунктам)

| Требование | Реализация |
|---|---|
| Объект вводится один раз и сохраняется | Экран «Объекты»: создаёте один раз, дальше используется как активный |
| Толщина слоя (например 6 см) | Поле в объекте, по умолчанию 6 см; норма = норма на 1 см × толщина — как вы подтвердили |
| Тонны → расстояние | Формула `масса / норму × 1000 / ширину` в `util/Calc.kt`, результат — большая зелёная карточка |
| Кнопки-маяки 10/20/30 т | Три больших кнопки, сразу выставляют массу и показывают расстояние |
| Расчёт проектной (фактической) нормы | Иконка-калькулятор в шапке главного экрана → `масса / площадь × 1000`, длину можно взять из GPS |
| Журнал по времени, сколько тонн положено | Экран «Журнал»: фильтр Сегодня/Неделя/Месяц/Всё, суммы тонн и метров |
| Ввод материала → сразу в справочник | Экран «Справочник»: материал сохраняется в базу сразу при добавлении |
| Видно вес, видно зелёным расстояние | Главный экран: масса сверху, результат — крупным зелёным текстом (56sp) |
| GPS-измерение расстояния | Старт при приезде машины → трекинг → факт. расстояние → кнопка "Факт. норма" |
| Привязка к Яндексу | См. пояснение ниже |

## Про GPS и Яндекс — как это устроено и почему

Есть два независимых механизма, и это осознанное решение:

1. **Измерение расстояния** — через встроенный в Android `LocationManager` (GPS-чип
   телефона напрямую, без Google Play Services и без Яндекс SDK). Это значит: не
   нужен API-ключ, не нужен интернет, работает в поле на трассе. Нажали "Старт GPS"
   при заезде машины → идёте вдоль укладки → приложение считает расстояние по прямой
   от точки старта до текущей позиции.
2. **Привязка к Яндексу** — кнопка с иконкой геометки открывает текущую GPS-точку
   в приложении Яндекс.Карты (если оно установлено на телефоне), либо в браузере.

Почему не встроенная карта Яндекс.MapKit прямо в приложении: полноценный SDK
Яндекс.Карт требует собственный API-ключ (бесплатный, но регистрируется на вашем
Яндекс-аккаунте — я не могу создать его за вас), плюс скачивание тайлов карты
требует мобильный интернет, которого на трассе за городом часто просто нет. Кнопка
"открыть в Яндекс.Картах" даёт привязку к Яндексу без этих двух проблем и работает
сразу после установки. Если позже захотите полноценную встроенную карту с треком —
это отдельная, более объёмная доработка, скажите, сделаю.

## Справочник материалов — важная оговорка

Все ~21 позиция из вашей таблицы (СТБ 1033-2016 / ТУ BY 100019869.001-2011) перенесены
в приложение вручную с фотографии. Строка, которую вы отметили (Плотная мелкозернистая
А,Б,В, плотность 2,5–2,9 т/м³) перенесена как 25,2 т/1000м² на 1 см / 100,4 на 4 см.
**Мелкие цифры на фото легко перепутать** (например 89,5 и 98,5) — откройте экран
«Справочник» и сверьте значения с оригиналом документа перед тем, как полагаться на
них в реальных расчётах материала. Исправить любое значение — два тапа (иконка
карандаша → новое число → Сохранить).

## Структура проекта

```
app/src/main/java/com/absapp/control/
├── data/         Room: сущности, DAO, база, репозиторий, сид справочника
├── location/      GpsTracker — измерение расстояния через LocationManager
├── util/          Calc.kt (формулы), Format.kt, MapIntents.kt (Яндекс)
├── viewmodel/      AppViewModel — состояние экрана, вся бизнес-логика
├── ui/            4 экрана (Укладка/Журнал/Объекты/Справочник) + диалоги + тема
└── MainActivity.kt
```

## Технические детали (на случай, если пригодится)

- Kotlin 1.9.24, Jetpack Compose (Material 3), Room 2.6.1, Navigation Compose 2.7.7
- minSdk 26 (Android 8.0+), targetSdk/compileSdk 34
- Никаких сторонних SDK с закрытыми API — только AndroidX-библиотеки

## Известные ограничения / что можно добавить дальше

- Нет облачной синхронизации между телефонами — данные только локальные (это было
  осознанным выбором ради офлайн-работы; если нужна синхронизация между несколькими
  бригадами, это отдельная функция).
- Нет экспорта журнала в Excel/PDF — можно добавить по запросу.
- Полноценная встроенная карта Яндекс.MapKit с треком — не включена по причинам выше,
  но код можно расширить, если у вас есть свой API-ключ Яндекса.
- Дистанция GPS считается по прямой от точки старта, не по накопленному пути — это
  точнее для укладки вдоль дороги, но если участок сильно петляет, точность снизится.
